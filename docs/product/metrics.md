# События, UTM-метки и проверка эффекта

Как мы узнаём, что бот возвращает людей на «Альфа-Курс» и не раздражает их. Код — [`app/events.py`](../../app/events.py).

## Что видит бот, а что — платформа

Бот знает, что он **показал** и что пользователь сделал **внутри бота**. Перехода по ссылке бот не видит: Telegram не сообщает о кликах. Переходы и покупки считает платформа по UTM-меткам, которые бот добавляет к каждой ссылке.

| Вопрос | Где ответ |
| --- | --- |
| Что бот показал и напомнил, что отключили | таблица `events` в PostgreSQL бота |
| Перешёл ли человек на платформу | аналитика платформы, по `utm_source=alfa_kurs_bot` |
| Купил ли курс после перехода | аналитика платформы, по той же сессии |

## События

Пишутся через `log_event(user_id, name, payload)`. Названия — константы в `app/events.py`.

| Событие | Когда | Что в `payload` |
| --- | --- | --- |
| `bot_started` | пользователь нажал `/start` | — |
| `question_asked` | бот ответил на вопрос | `kind`: `answer`, `clarify` или `no_answer`; `sources`: число источников |
| `material_shown` | бот показал материал | `material_id`, `kind`, `access`, `place`: `answer`, `recommendation`, `reminder` |
| `reminder_created` | пользователь подтвердил напоминание | `kind`, `recurring` |
| `reminder_sent` | напоминание отправлено | `reminder_id`, `kind` |
| `reminder_changed` | нажато «Реже», пауза или возобновление | `reminder_id`, `action` |
| `reminder_disabled` | нажато «Отключить» или напоминание удалено | `reminder_id`, `kind` |
| `profile_updated` | из сообщения добавлены сведения о бизнесе | `fields`: названия полей, без значений |
| `profile_reset` | пользователь удалил профиль | — |
| `bot_blocked` | пользователь заблокировал бота | — |

**Чего в журнале нет.** Текста сообщений, имени, username, телефона: `log_event` сам убирает такие поля из `payload`. Сбой записи не ломает ответ — ошибка уходит в лог.

## UTM-метки

`tracked_url(url, campaign, content)` добавляет метки к ссылкам на `kurs.alfabank.ru`; чужие ссылки не трогает.

| Метка | Значение |
| --- | --- |
| `utm_source` | `alfa_kurs_bot` |
| `utm_medium` | `telegram` |
| `utm_campaign` | откуда ссылка: `answer`, `recommendation`, `reminder_learning`, `reminder_tax`, `starter` |
| `utm_content` | вид материала (`article`, `course`, …) или его id |

В метках нет ничего о пользователе: ни Telegram ID, ни имени. Свободный текст в метку записать нельзя — функция принимает только латиницу, цифры, `-` и `_`.

## Метрики

| Метрика | Как считаем | Зачем |
| --- | --- | --- |
| Переходы на платформу | сессии платформы с `utm_source=alfa_kurs_bot`, в разрезе `utm_campaign` | главный показатель возврата |
| Конверсия в покупку | покупки в сессиях с меткой бота ÷ переходы | приносит ли бот продажи |
| Активные дни | дни с заходом на платформу на пользователя за 4 недели | возвращается ли человек регулярно |
| Доля ответов по базе | `question_asked` с `kind = answer` ÷ все `question_asked` | качество базы и поиска |
| Доля «в базе нет» | `kind = no_answer` ÷ все `question_asked` | каких тем не хватает |
| Отключения напоминаний | `reminder_disabled` ÷ `reminder_sent` | ограничитель: не надоедаем ли |
| Блокировки бота | пользователи с `bot_blocked` ÷ пользователи с `bot_started` | ограничитель: сигнал раздражения |

Пример запроса — доля отключений по видам напоминаний за последние 28 дней:

```sql
SELECT payload->>'kind' AS kind,
       count(*) FILTER (WHERE name = 'reminder_disabled')::float
         / NULLIF(count(*) FILTER (WHERE name = 'reminder_sent'), 0) AS disabled_share
FROM events
WHERE name IN ('reminder_sent', 'reminder_disabled')
  AND occurred_at >= now() - interval '28 days'
GROUP BY 1;
```

## Как проверить эффект после внедрения

**A/B-тест.** Пользователей платформы случайно делим на две группы: одной предлагаем бота, другой нет. Срок — 4 недели.

- **Смотрим:** конверсию в покупку курса и число активных дней на платформе.
- **Ограничители:** доля блокировок бота и доля отключённых напоминаний. Если они растут — бот надоедает, даже когда переходов больше.
- **Внутри бота** отдельно сравниваем частоту напоминаний (например, раз в неделю против двух) по тем же ограничителям.

**Что считаем успехом:** в группе с ботом больше активных дней и покупок, а блокировок и отключений — не больше заранее выбранного порога.

**Ограничения прототипа.** В хакатоне у нас нет доступа к аналитике платформы, поэтому переходы и покупки мы не измеряем — показываем только, что ссылки размечены и события пишутся.
