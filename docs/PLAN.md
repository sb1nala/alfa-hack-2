# План: ИИ-помощник «Альфа-Курса» в Telegram (трек 2)

Hack&Change 2026, кейс Альфа-Банка «Альфа-Курс: знания в нужный момент».
Кто что делает — в [TEAM.md](TEAM.md). Правила для ИИ-инструментов — в [AGENTS.md](../AGENTS.md).

**Цель:** Telegram-бот, который отвечает предпринимателю по базе знаний «Альфа-Курса», подбирает материалы под его бизнес и напоминает об обучении и налоговых сроках — так, чтобы он чаще возвращался на платформу и покупал курсы.

**Архитектура:** один Python-процесс в Docker: бот на long polling (публичный адрес не нужен), SQLite в volume, поиск по базе знаний внутри процесса, фоновый цикл рассылки напоминаний. Наружу ходим только в LLM API.

**Стек (предложение, утверждаем на этапе 0):** Python 3.12, aiogram 3, SQLite, гибридный поиск (BM25 + локальные эмбеддинги через ONNX, без torch), LLM через OpenAI-совместимый клиент (`LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`), pytest, Docker Compose.

## 1. Что требует кейс

| № | Требование | Где закрываем |
|---|-----------|---------------|
| 1 | Отвечать на вопросы по базе знаний | `kb`, `assistant` |
| 2 | Уточнять неясные вопросы, честно говорить «в базе нет» | `assistant` (три типа ответа) |
| 3 | Собирать сведения о бизнесе в диалоге, персонализировать | `profile` |
| 4 | Рекомендовать бесплатные и платные материалы | `recs` |
| 5 | Разовые и повторяющиеся напоминания, в т.ч. налоговые сроки по режиму | `reminders`, `tax_calendar.yaml` |
| 6 | Менять частоту и отключать напоминания | `reminders`, меню бота |
| 7 | Объяснить, как бот возвращает на платформу, и как это проверить | `events`, раздел 7, презентация |

Сценарии, по которым будет проверять жюри (приложение 2 кейса):

1. Вопрос по теме из базы → ответ на её основе + подходящий материал.
2. «Напомни…» → бот уточняет данные → подтверждает → присылает вовремя → пользователь меняет частоту или отключает.
3. Неоднозначный вопрос или вопрос вне базы → уточнение или честное «этого в базе нет».

## 2. Жёсткие ограничения

- **Данные кейса нельзя публиковать.** Репозиторий сейчас публичный, поэтому папка `data/` в `.gitignore`, в коммиты не попадает ничего из выгрузки: ни файлы, ни их куски в тестах, ни готовый индекс.
- **Платные материалы:** подробное содержание не раскрываем. Только короткая польза + ссылка из данных. Текст платных материалов не уходит во внешний LLM.
- **Во внешние API** — только нужные фрагменты, без персональных данных. В запросе к LLM нет имени, username и Telegram ID.
- **Никакой навязчивости:** бот сам пишет только то, о чём пользователь попросил; у каждого напоминания кнопка «отключить».
- **Секреты** не коммитим. В репозитории только `.env.example`.
- **Запуск одной командой:** `docker compose up --build` после заполнения `.env`.
- Интеграции с банком и госсервисами не нужны.

## 4. Как это работает

```
Telegram ──> bot (aiogram) ──> assistant.reply()
                                 ├─ profile: что знаем о бизнесе, что нового в сообщении
                                 ├─ намерение: вопрос | напоминание | разговор
                                 ├─ kb.search(): фрагменты базы знаний
                                 ├─ recs.recommend(): материалы под профиль и вопрос
                                 └─ llm: ответ строго по фрагментам
цикл раз в 30 с ──> reminders.due() ──> отправка ──> пересчёт следующего срока
всё важное ──> events (для метрик)
```

**Ответ на вопрос.** Ищем фрагменты; LLM получает только их и возвращает один из трёх типов:

- `answer` — ответ по фрагментам + источники + следующий шаг;
- `clarify` — вопрос слишком общий, один уточняющий вопрос с кнопками-вариантами;
- `no_answer` — релевантного в базе нет: честно говорим об этом и предлагаем ближайшие темы.

Если лучший результат поиска ниже порога — `no_answer` без обращения к LLM (порог подбираем на тестовом наборе).

**Профиль.** Поля: стадия бизнеса, сфера, форма (ИП/ООО/самозанятый), налоговый режим, опыт, текущая задача, часовой пояс. Анкета не обязательна: на старте два-три вопроса кнопками с «Пропустить», остальное бот достаёт из сообщений. `/profile` — посмотреть, исправить, удалить. При пустом профиле бот всё равно полезен: отвечает на вопрос и даёт общую стартовую подборку.

**Рекомендации.** До трёх материалов: отбор по теме вопроса, затем порядок по совпадению с профилем (стадия, уровень, формат). У каждого — одна строка «почему вам». Платный: польза в одном предложении и ссылка, без пересказа. Уже показанное не повторяем.

**Напоминания.** Три вида: своё («напомни в пятницу сверить кассу»), учебное («напоминай продолжать курс по вторникам»), налоговое (по режиму из профиля, из `tax_calendar.yaml`). Текст на естественном языке разбирает LLM → бот показывает, что понял → пользователь подтверждает кнопкой. Повторы храним как RRULE. `/reminders` — список, сменить частоту, пауза, удалить. Цикл читает сроки из SQLite, поэтому перезапуск ничего не теряет.

**Не раздражать.** Тихие часы 21:00–09:00 по времени пользователя (сообщение уезжает на утро), не больше двух сообщений по инициативе бота в день, кнопки «Отключить» и «Реже» под каждым напоминанием, никаких рассылок без подписки.

## 5. Структура кода и договорённости между модулями

```
app/
  main.py            запуск бота и цикла напоминаний
  config.py          переменные окружения
  models.py          общие типы (ниже)
  llm/client.py      complete()
  kb/ingest.py       выгрузка -> материалы и фрагменты
  kb/search.py       search()
  assistant/core.py  reply()
  profile/service.py get(), update_from_message(), reset()
  recs/service.py    recommend()
  reminders/service.py   create(), list_for(), set_schedule(), pause(), delete(), due()
  reminders/parse.py     parse_request()
  reminders/tax_calendar.yaml
  storage/db.py      SQLite, миграция при старте
  events.py          log_event()
  bot/               хендлеры, клавиатуры, тексты
tests/
eval/                тестовые вопросы и профили (придуманные, не из выгрузки)
data/                выгрузка кейса — НЕ в git
```

Общие типы — их меняем только по согласованию в чате команды:

```python
@dataclass
class UserProfile:
    user_id: int
    business_stage: str | None = None   # "idea" | "starting" | "running" | "growing"
    industry: str | None = None
    legal_form: str | None = None       # "ip" | "ooo" | "self_employed"
    tax_regime: str | None = None       # "usn_income" | "usn_income_expense" | "ausn" | "psn" | "npd" | "osno"
    experience: str | None = None       # "beginner" | "experienced"
    current_goal: str | None = None
    timezone: str = "Europe/Moscow"

@dataclass
class Material:
    id: str
    title: str
    url: str
    is_paid: bool
    summary: str
    topics: list[str]
    format: str | None = None
    level: str | None = None

@dataclass
class Chunk:
    material: Material
    text: str
    score: float

@dataclass
class Recommendation:
    material: Material
    reason: str

@dataclass
class Answer:
    kind: Literal["answer", "clarify", "no_answer"]
    text: str
    sources: list[Material]
    recommendations: list[Recommendation]
    options: list[str]                  # варианты для clarify, иначе пусто

@dataclass
class Reminder:
    id: int
    user_id: int
    kind: Literal["custom", "learning", "tax"]
    text: str
    next_run_at: datetime               # UTC
    rrule: str | None                   # None = разовое
    active: bool
```

Функции на границах модулей:

```python
# llm/client.py
async def complete(messages: list[dict], json_schema: dict | None = None) -> str | dict
# kb/search.py
def search(query: str, k: int = 6) -> list[Chunk]
# assistant/core.py
async def reply(user_id: int, text: str) -> Answer
# profile/service.py
def get(user_id: int) -> UserProfile
async def update_from_message(user_id: int, text: str) -> UserProfile
def reset(user_id: int) -> None
# recs/service.py
def recommend(profile: UserProfile, query: str, exclude_ids: set[str], k: int = 3) -> list[Recommendation]
# reminders/parse.py
async def parse_request(text: str, profile: UserProfile, now: datetime) -> Reminder | str   # str = что уточнить
# reminders/service.py
def create(reminder: Reminder) -> Reminder
def list_for(user_id: int) -> list[Reminder]
def set_schedule(reminder_id: int, rrule: str | None, next_run_at: datetime) -> Reminder
def pause(reminder_id: int, active: bool) -> None
def delete(reminder_id: int) -> None
def due(now: datetime) -> list[Reminder]
# events.py
def log_event(user_id: int, name: str, payload: dict | None = None) -> None
```

Точные поля `Material` уточняем после знакомства с выгрузкой (этап 0).

## 7. Возврат на платформу и проверка эффекта

Как возвращаем: ссылка на материал в каждом ответе; учебные напоминания ведут на конкретный урок; налоговое напоминание приходит с материалом «как это сделать»; после ответа — предложение следующего шага.

Что считаем (`events` + UTM-метки в ссылках): переходы из бота на платформу, покупки после перехода, дни с заходом на платформу, долю отключённых напоминаний и блокировок бота (сигнал раздражения).

Как проверять после внедрения: A/B-тест — часть пользователей получает бота, часть нет; сравниваем конверсию в покупку и число активных дней за 4 недели; ограничители — доля блокировок бота и отписок от напоминаний. Внутри бота отдельно тестируем частоту напоминаний.

## 8. Что решить на этапе 0

1. **LLM-провайдер.** Требования: жюри может получить ключ по инструкции из README, хорошо работает с русским, умеет отдавать JSON. Код от провайдера не зависит (OpenAI-совместимый клиент), так что выбираем по доступности и цене. Кандидаты — YandexGPT, GigaChat, OpenRouter; актуальные условия проверить.
2. **Эмбеддинги.** Предложение — локальная мультиязычная модель через ONNX: тексты не уходят наружу, жюри не нужен второй ключ. Если образ выйдет слишком тяжёлым — остаёмся на BM25 с перестановкой результатов через LLM.
3. **Публичный или приватный репозиторий.** В публичном данные держать нельзя — жюри кладёт свою копию выгрузки в `data/` по README. Приватный + доступ жюри убирает риск случайной публикации.
4. **Даты налогового календаря** сверяет человек по nalog.gov.ru, а не модель по памяти. В боте — оговорка «проверьте срок на сайте ФНС».

## 9. Где скорее всего сломается

1. Бот уверенно отвечает на вопрос, которого нет в базе → в тестовом наборе обязательно вопросы вне базы, ответ на них должен быть `no_answer`.
2. Пересказ платного материала → тест: в ответе нет текста платных фрагментов, только описание и ссылка.
3. Напоминание пришло не в то время из-за часового пояса → тесты на разбор «завтра в 9» для Москвы и Владивостока; в базе только UTC.
4. Напоминания пропали после перезапуска контейнера → тест: создать, перезапустить, дождаться.
5. Жюри запускает без данных или без ключа → понятная ошибка при старте, что именно не найдено и куда положить.
