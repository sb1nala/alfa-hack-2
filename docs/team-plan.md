Дедлайн — **16.11.2026** (понедельник; точное время приёма уточнить, планируем сдать до 12:00). Цель на 12.11: в Docker работает сквозной путь «вопрос в Telegram → поиск по базе знаний → ответ с источником и материалом» и приходит разовое напоминание. ## Как работаем

- В `main` — только через PR; каждый PR смотрит один человек из команды.
- Договорённость между модулями — типы и сигнатуры из [`architecture.md`](architecture.md). Меняем их только отдельным PR с упоминанием тех, кого это касается.
- `AGENTS.md` (Codex) и `CLAUDE.md` (Claude Code) — общие правила для ИИ, чтобы все писали код в одном стиле.
- Каждый правит только свои папки.
- Утром 15-минутный созвон: что сделал, что делаю, где застрял.
- Каждый вечер в 21:00 — слияние готового и `docker compose up --build` с нуля.
- Данные кейса и токены — никогда в репозиторий. Токен бота и ключ LLM передаём лично.
- Один токен бота — один запущенный экземпляр. Для своей разработки каждый заводит своего бота у @BotFather.

## Стартовые промпты

**Бот и напоминания → Codex**

```text
Репо sb1nala/alfa-hack-2 — хакатон Hack&Change 2026, Telegram-помощник для платформы «Альфа-Курс».
Прочитай AGENTS.md, docs/team-plan.md и docs/architecture.md. Моя роль — «2. Бот и напоминания».
Стек: Python 3.12, aiogram 3, PostgreSQL 16 через asyncpg (без ORM и Alembic), pytest.
Подключение уже есть: app/storage/db.py (connect, pool, close), схема — app/storage/schema.sql,
она применяется при каждом старте, поэтому только CREATE TABLE IF NOT EXISTS и подобное.
Добавь в schema.sql таблицы users, profiles, reminders, events, shown_materials; время — timestamptz в UTC. Затем app/reminders/service.py по сигнатурам из docs/architecture.md:
create, list_for, set_schedule, pause, delete, due. Повторы — строка RRULE, считать через python-dateutil.
Сначала предложи схему таблиц и список тестов, потом пиши код. Тесты с базой помечай так, чтобы они пропускались без DATABASE_URL; логику расписаний держи
в чистых функциях и тестируй без базы.
Одна задача — одна ветка feat/<задача> и один PR.
```

**Рекомендации и профиль → Claude Code**

```text
Репо sb1nala/alfa-hack-2 — Telegram-помощник для платформы «Альфа-Курс». Прочитай AGENTS.md,
docs/architecture.md и docs/data.md. Моя роль — «3. Продукт, рекомендации, QA и документация».
Реализуй app/recs/service.py: recommend(profile, query, exclude_ids, k=3) -> list[Recommendation].
Материалы бери из app.kb.ingest (поля Material: kind, access, topics, tags, industries, popularity).
Отбор — по поиску app.kb.search и совпадению тегов с profile.current_goal; порядок — совпадение отрасли
и опыта с профилем, затем popularity. У каждой рекомендации reason — одна строка «почему вам» без пересказа
содержания. Для материалов с access != "open" reason строится только из названия и summary.
Пустой профиль не ошибка: тогда порядок только по вопросу и популярности.
Тесты — на придуманных материалах, данные кейса в репозиторий не попадают.
```

**Налоговый календарь → Claude (режим Research)**

```text
Составь календарь обязательных платежей и отчётов на 2026 и 2027 годы для малого бизнеса в России
по режимам: УСН «доходы», УСН «доходы минус расходы», АУСН, патент, НПД (самозанятые), ОСНО,
плюс страховые взносы ИП за себя. Для каждого события: режим, кто платит (ИП / ООО), что именно,
срок (дата), как часто повторяется, ссылка на страницу nalog.gov.ru или на норму НК РФ.
Учитывай перенос сроков с выходных. Если в чём-то не уверен — пометь явно, не додумывай.
Формат ответа — YAML, одно событие на запись.
```

Каждую дату из ответа сверяет человек по первоисточнику — в бота идут только проверенные.

**Тестовый набор → Claude**

```text
Я тестирую Telegram-бота, который отвечает предпринимателям по базе знаний образовательной платформы
для малого бизнеса (статьи о налогах, регистрации, найме, маркетинге, маркетплейсах, шаблоны документов,
словарь терминов, курсы). Придумай 40 вопросов так, как их пишут живые люди, без терминов и с опечатками:
15 обычных вопросов по этим темам; 8 слишком общих, где нужно уточнение («как платить налоги?»);
8 не по теме базы (медицина, спорт, погода, личные финансы); 5 про выбор обучения («есть ли курс по…»);
4 просьбы о напоминании. Для каждого укажи ожидаемое поведение: answer, clarify, no_answer или reminder.
Формат — YAML.
```

Совет по Claude Pro: лимиты считаются окнами по 5 часов — длинное исследование (налоговый календарь) ставить в начало окна, код писать по одной задаче на сессию, между задачами `/clear`. Совет по Codex: одна задача — один PR, так проще ревьюить.
